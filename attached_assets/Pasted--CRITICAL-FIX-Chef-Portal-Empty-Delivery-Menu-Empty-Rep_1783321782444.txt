# CRITICAL FIX — Chef Portal Empty + Delivery Menu Empty
### (ቲጂ ምግብ ቤት — Replit Agent)

Two specific bugs are confirmed from live testing. Fix these exactly as described. Do not refactor anything else. Do not "improve" unrelated code. Read → diagnose → fix → verify each one.

---

## THE EVIDENCE

From a live screenshot with three browsers open simultaneously:
- **Super Admin kitchen page** → shows order `TGQW0E9151` (1x Doro Wat) with status "Preparing" — the order EXISTS in the database
- **Meron Tadesse's Chef Portal** (`/chef`) → shows "No new orders — you'll hear an alert when one arrives" — EMPTY despite the order existing
- **Solomon Bekele's Delivery Portal** (`/delivery`) → menu picker shows "No items match search" with only an "All" filter button and no items — menu NOT loading

This means:
1. The Chef Portal is either calling the wrong API endpoint, being rejected by middleware, or branch-filtering to an empty result
2. The Delivery Portal menu fetch is being rejected or returning empty for the `delivery_staff` role

---

## FIX 1 — CHEF PORTAL: ORDERS NOT APPEARING

### Step 1 — Find the kitchen queue API endpoint

Search the backend (`artifacts/api-server/src/routes/`) for the route that serves kitchen orders. It will be something like:
- `GET /api/kitchen/queue`
- `GET /api/orders/kitchen`
- `GET /api/kitchen/orders`

Read that route handler completely.

### Step 2 — Check the middleware on that route

Look at the `requireRole(...)` or `requireAuth(...)` call on that specific route. After Phase 5 and Phase 6 changes, it may have been accidentally restricted to `super_admin` and `branch_manager` only — excluding `chef`.

**The fix:** The kitchen queue GET endpoint must allow `chef`, `super_admin`, and `branch_manager`:
```typescript
router.get('/queue', requireRole('chef', 'super_admin', 'branch_manager'), async (req, res) => {
```

### Step 3 — Check the branch_id filter in the query

The kitchen queue query filters orders by `branch_id`. Read the actual SQL/Drizzle query. Check what value it uses for `branch_id`:

- If it reads `req.user.branchId` from the JWT — is Meron's chef account actually assigned to a branch? Check the `users` table: `SELECT id, name, role, branch_id FROM users WHERE name LIKE '%Meron%';`
- If `branch_id` is NULL on Meron's account, the query returns zero results. Fix: assign her to a branch in the database OR in the Staff management UI.

Run this SQL to check:
```sql
SELECT id, name, role, branch_id, chef_status FROM users WHERE role = 'chef';
SELECT id, name, role, branch_id FROM users WHERE role = 'delivery_staff';
```

If `branch_id` is NULL for any staff — UPDATE them:
```sql
UPDATE users SET branch_id = 1 WHERE role = 'chef' AND branch_id IS NULL;
UPDATE users SET branch_id = 1 WHERE role = 'delivery_staff' AND branch_id IS NULL;
```
(Replace `1` with the actual branch ID from the `branches` table: `SELECT id, name FROM branches;`)

### Step 4 — Check the Chef Portal frontend API call

Open `artifacts/tg-erp/src/pages/chef-portal.tsx` (or wherever the Chef Portal component lives). Find the API fetch call for the kitchen queue. Check:

1. Is it calling the correct endpoint URL? (e.g., `/api/kitchen/queue` vs `/api/orders/kitchen`)
2. Is it sending the Authorization header with the JWT token?
3. Open browser DevTools on Meron's Chef Portal → Network tab → find the kitchen queue API call → what status code does it return? What does the response body say?

If it returns `403` → middleware is blocking the chef role (fix in Step 2 above)
If it returns `200` with empty array `[]` → branch_id mismatch (fix in Step 3 above)
If it returns `404` → wrong endpoint URL being called from frontend

### Step 5 — Check Socket.IO room joining in Chef Portal

Find where the Chef Portal connects to Socket.IO. It should join:
```javascript
socket.emit('join', { room: `branch:${user.branchId}:kitchen` });
// or
socket.join(`branch:${user.branchId}:kitchen`);
```

Find where the server emits `order:new` when an order is created (in the POST /api/orders handler). It should emit to:
```javascript
io.to(`branch:${order.branchId}:kitchen`).emit('order:new', { order });
```

Confirm the room name used in the emit EXACTLY matches the room name the Chef Portal joins. Even one character difference means the chef never receives the event.

## FIX 2 — DELIVERY PORTAL: MENU NOT LOADING

### Step 1 — Find the menu API endpoint

Search the backend for the menu items route. It will be something like:
- `GET /api/menu/items`
- `GET /api/menu`
- `GET /api/menu-items`

### Step 2 — Check the middleware

Read the middleware on the menu GET endpoint. After Phase 5 role-restriction work, it is very likely restricted to admin-only roles. 

**The fix — menu READ must be accessible to ALL authenticated roles:**
```typescript
// GET menu items — ALL authenticated users can read (chefs, delivery staff, admins, etc.)
router.get('/items', requireAuth, async (req, res) => {  // requireAuth only, NOT requireRole

// POST/PUT/DELETE — admin only
router.post('/items', requireRole('super_admin', 'branch_manager'), async (req, res) => {
router.put('/items/:id', requireRole('super_admin', 'branch_manager'), async (req, res) => {
router.delete('/items/:id', requireRole('super_admin', 'branch_manager'), async (req, res) => {
```

`requireAuth` = any valid JWT regardless of role
`requireRole(...)` = only specific roles

### Step 3 — Check the Delivery Portal frontend menu fetch

Open the Delivery Portal component. Find where it fetches the menu. Check:
1. Is the Authorization header being sent with the delivery staff JWT?
2. Open browser DevTools on Solomon's (not only for solomon, for all deliverymans registered okay) Delivery Portal → Network tab → find the menu API call → what status does it return?

If `403` → fix middleware (Step 2)
If `200` with empty array → check if menu items exist in the DB and are linked to the correct branch:
```sql
SELECT COUNT(*) FROM menu_items;
SELECT COUNT(*) FROM menu_items WHERE branch_id = 1; -- use actual branch id
SELECT COUNT(*) FROM menu_items WHERE available = true;
```

### Step 4 — Check branch scoping on menu query

The menu query likely filters by `branch_id`. Check what branch_id it uses:
- If it uses `req.user.branchId` from JWT AND Solomon's account has `branch_id = NULL` → menu returns empty
- The branch fix from Fix 1 Step 3 above covers this — fix NULL branch_ids for all staff
