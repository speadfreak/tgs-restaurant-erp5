## WHAT THIS SYSTEM IS

TG's Restaurant ERP is a **delivery-only** Ethiopian restaurant management system operating in Dubai, UAE. It has **four separate role-based portals** all served from one backend:

| Portal | URL | Who uses it |
|---|---|---|
| Admin Command Center | `/` or `/admin` | Super Admin, Branch Manager |
| Chef Portal | `/kitchen` | Kitchen staff only |
| Deliveryman Portal | `/delivery` | Delivery staff only |
| Addis Ababa Portal | `/addis` | Ethiopia-based supply staff only |
| Customer Webapp | `/menu-public` | Public customers (no login) |
| Order Tracker | `/track/:code` | Public customers (no login) |

Each role can **only** access their own portal. Login redirects automatically based on role. This is enforced server-side — not just in the UI.

## STEP 2 — SET UP ENVIRONMENT VARIABLES

Go to Replit's **Secrets** panel (the lock icon in the sidebar) and add every variable below. Do not put secrets in `.env` files committed to the repo.

**Required to boot (system will crash without these):**

| Secret Key | Value |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string — set this up in Step 3 first |
| `JWT_SECRET` | Any random 64-character string |
| `JWT_REFRESH_SECRET` | A different random 64-character string |
| `SETTINGS_ENCRYPTION_KEY` | Any random 32-character string (used to encrypt API keys stored in DB settings table) |
| `NODE_ENV` | `development` |
| `PORT` | `3000` |

**Required for full functionality (set to `placeholder` for now if you don't have them yet):**

| Secret Key | Value |
|---|---|
| `TWILIO_ACCOUNT_SID` | `placeholder` |
| `TWILIO_AUTH_TOKEN` | `placeholder` |
| `TWILIO_WHATSAPP_NUMBER` | `placeholder` |
| `SENDGRID_API_KEY` | `placeholder` |

**Scan the codebase for any other `process.env.` references not listed above and add those to Secrets too.** A missing env variable causes silent crashes — find them all before starting.

## STEP 3 — SET UP POSTGRESQL DATABASE

1. In Replit, go to the **Database** tab in the sidebar and create a new PostgreSQL database. Copy the connection string it gives you.
2. Add it as `DATABASE_URL` in Secrets (from Step 2).
3. Run the database schema push. Look inside `lib/db/` for the Drizzle config — the command is likely one of:
```bash
cd lib/db && npx drizzle-kit push
```
or from root:
```bash
pnpm run db:push
```
Run whichever exists. Do not skip this — the server will crash with "relation does not exist" errors without it.

4. Run the seed script to populate demo data (users, branches, menu items, sample orders):
```bash
pnpm run db:seed
```
or:
```bash
cd scripts && npx tsx src/seed.ts
```

5. Confirm tables exist by running a quick check:
```bash
psql $DATABASE_URL -c "\dt"
```
You should see 20+ tables including `users`, `orders`, `menu_items`, `branches`, `lottery_entries`, `import_shipments`, `settings`, etc.

## STEP 4 — INSTALL ALL DEPENDENCIES

This is a pnpm monorepo. **Always install from the root — never cd into sub-folders and run install separately.**

```bash
pnpm install
```

If pnpm is not available:
```bash
npm install -g pnpm
pnpm install
```

If you get peer dependency errors, read them carefully — do not use `--force`. Fix the root cause (usually a Node version issue — this project requires Node 18+).

Check the root `package.json` for the dev script. It likely starts everything in parallel:
