### 4.1 Chef Commission by Percentage

The delivery staff commission is a flat AED rate per delivery (already working).
Chef commission must work differently — **percentage of order total**.

**Backend changes needed:**

In `artifacts/api-server/src/routes/orders.ts` or wherever commissions are recorded when an order is marked "ready" by a chef:

```typescript
// When chef marks order ready, calculate commission:
const chefCommissionPercent = await getSetting('chef_commission_percent'); // e.g. "10" = 10%
const percent = parseFloat(chefCommissionPercent || '0');
const commissionAmount = (order.totalAed * percent) / 100;

await db.insert(commissions).values({
  userId: chefUserId, // from JWT
  orderId: order.id,
  amountAed: commissionAmount.toFixed(2),
  type: 'chef_percent',
  createdAt: new Date(),
});
```

Add `chef_commission_percent` to the settings defaults (e.g. default `"5"` = 5%).

**Admin Settings UI:**
Add a `chef_commission_percent` field in Settings → System or a new "Payroll" section:
- Label: "Chef Commission (%)"
- Input: number field (0–100)
- Description: "Percentage of each order total paid to the chef who prepared it"

**Chef Portal display:**
In `chef-portal.tsx`, show the chef's commission stats:
- Today's orders prepared
- Today's commission earned (sum of chef commissions for today in UAE time)
- Formula shown: e.g. "5% per order"
- Pull from the commissions table filtered by `userId` = logged-in chef and `type = 'chef_percent'`

### 4.2 Lottery Persistence Fix

**The problem:** The lottery engine currently uses "today" as the filter for eligible entries, which means at midnight UAE time the entries disappear before the admin has drawn the lottery.

**The fix:** The lottery should persist entries until the admin explicitly runs the draw — NOT reset at midnight.

**Backend changes in `artifacts/api-server/src/routes/lottery.ts`:**

Change the entries query from filtering by `draw_date = today` to filtering by entries that have not yet been assigned to a completed draw:

```typescript
// Show all entries where no completed draw has claimed them yet
// i.e. is_winner = false AND draw_id IS NULL (or however pending state is tracked)
```

The key rule: **entries only disappear from the active lottery pool after the admin successfully runs a draw** — never based on time/date alone.

**Frontend in `lottery.tsx`:**
- Remove any date-based filtering on the active entries display
- Show all entries where draw is not yet completed
- The count badge should show total pending entries, not "today's" entries
