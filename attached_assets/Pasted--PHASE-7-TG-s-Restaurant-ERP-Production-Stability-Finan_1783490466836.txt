## TIER 1 — CRITICAL PRODUCTION FIXES

### FIX 1 — SOCKET.IO NOT WORKING IN PRODUCTION (root cause of empty portals)

**The problem:** Socket.IO works on Replit (HTTP/WS) but fails on Render (HTTPS/WSS). In production, WebSocket connections must use `wss://` not `ws://`. If the Socket.IO client is connecting to a hardcoded `ws://` URL or falling back to polling incorrectly, real-time updates between portals will silently fail.

**Fix the Socket.IO client connection** in `artifacts/tg-erp/src/hooks/use-socket.ts`:

```typescript
const socket = io(import.meta.env.VITE_API_URL || window.location.origin, {
  withCredentials: true,
  transports: ['websocket', 'polling'], // try websocket first, fall back to polling
  secure: true, // force WSS in production
  reconnection: true,
  reconnectionAttempts: 5,
  reconnectionDelay: 1000,
});
```

**Fix the Socket.IO server** in `artifacts/api-server/src/lib/socket.ts` — confirm these options are set:
```typescript
const io = new Server(httpServer, {
  cors: {
    origin: process.env.FRONTEND_URL ? process.env.FRONTEND_URL.split(',') : ['http://localhost:5173'],
    credentials: true,
    methods: ['GET', 'POST'],
  },
  transports: ['websocket', 'polling'],
  allowEIO3: true, // backwards compatibility
});
```

**Also confirm** the Socket.IO client re-joins rooms after reconnect — must use `socket.on('connect', ...)` not `socket.once('connect', ...)`:
```typescript
socket.on('connect', () => {
  if (user?.branchId) {
    socket.emit('join_room', `branch:${user.branchId}`);
    socket.emit('join_room', `branch:${user.branchId}:${roleRoom}`);
  }
});
```

### FIX 5 — ALL ADMIN PAGES SHOWING ERRORS / NOT LOADING CONTENT

**Systematic fix for all pages that show errors in production:**

For every admin page that shows an error or empty state, the issue is one of:
- API call using wrong base URL (hardcoded localhost instead of VITE_API_URL)
- API endpoint returning 500 due to missing env var or DB connection issue
- Missing error boundary showing blank page instead of useful error

**Fix globally:**

1. Search for any remaining `localhost:3000` or `localhost:5173` hardcoded in frontend source:
```bash
grep -r "localhost:3000\|localhost:5173" artifacts/tg-erp/src --include="*.ts" --include="*.tsx"
```
Replace every instance with `import.meta.env.VITE_API_URL || ''`

2. Add a global error boundary component that wraps each page — shows a user-friendly "Something went wrong — [error message]" instead of a blank screen. This makes debugging in production far easier.

3. For every page that fetches data on load, add proper loading states and error states:
```typescript
if (isLoading) return <LoadingSpinner />
if (error) return <ErrorMessage message={error.message} />
if (!data || data.length === 0) return <EmptyState message="No data yet" />
```

4. In the backend, add a global error handler at the end of `app.ts`:
```typescript
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  console.error('Unhandled error:', err);
  res.status(500).json({ 
    error: process.env.NODE_ENV === 'production' ? 'Internal server error' : err.message 
  });
});
```

## TIER 2 — NEW FEATURES

### FEATURE 1 — FINANCE PORTAL (New Role + New Portal)

#### 1.1 New Role: `finance_staff`

Add `finance_staff` to the RBAC role enum alongside existing roles.

**Access permissions:**
- Can access: Finance Portal only (`/finance-portal/*`)
- Cannot access: Admin Command Center, Chef Portal, Delivery Portal, Addis Portal
- Login redirects automatically to `/finance-portal`

#### 1.2 Finance Portal — Staff View (`/finance-portal`)

A dedicated, focused portal for finance staff to log expenses and income entries. Clean, professional design matching the TG's Restaurant dark theme.

**Page 1 — Log New Entry:**
Form with fields:
- Entry Type: toggle between **Income** / **Expense**
- Category (dropdown, admin-configurable):
  - Income categories: "Delivery Order", "Catering", "Other Income"
  - Expense categories: "Ingredients", "Staff Wages", "Rent", "Utilities", "Marketing", "Maintenance", "Transport", "Other Expense"
- Amount (AED) — number input
- Description — text field
- Date — date picker (defaults to today)
- Branch — dropdown (scoped to their assigned branch)
- Reference/Receipt Number — optional text
- Notes — optional textarea
- Submit button

On submit → creates real entry in `finance_entries` table → appears immediately in Admin Finance module.

**Page 2 — My Recent Entries:**
- Table of all entries logged by this staff member
- Columns: Date, Type (Income/Expense badge), Category, Amount AED, Description, Branch, Status
- Last 30 days by default, date range filterable
- Edit button (can edit entries within 24 hours of creation — locked after that for audit integrity)
- Delete button (only within 1 hour of creation, with confirmation)

**Page 3 — Summary:**
- Simple daily totals for their branch: today's income logged, today's expenses logged, net
- Not the full P&L — just what they've personally entered today and this week

**Portal header:**
- Finance staff name + role badge
- Branch name
- "Finance Portal" title with accounting icon
- Logout button

#### 1.3 New Database Table: `finance_entries`

```sql
CREATE TABLE finance_entries (
  id SERIAL PRIMARY KEY,
  branch_id INTEGER NOT NULL REFERENCES branches(id),
  logged_by_user_id INTEGER NOT NULL REFERENCES users(id),
  entry_type VARCHAR(10) NOT NULL CHECK (entry_type IN ('income', 'expense')),
  category VARCHAR(100) NOT NULL,
  amount_aed DECIMAL(10,2) NOT NULL,
  description TEXT NOT NULL,
  reference_number VARCHAR(100),
  notes TEXT,
  entry_date DATE NOT NULL DEFAULT CURRENT_DATE,
  is_locked BOOLEAN DEFAULT FALSE, -- locked after 24h
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### FEATURE 3 — LOTTERY MESSAGE IN DELIVERYMAN PORTAL

When a delivery staff member has an order in "Delivered" status in their My Deliveries tab, show a **"Copy Thank You Message"** button on that order card.

Clicking it copies this bilingual message to clipboard:

```
ቲጂ ምግብ ቤት ✨

ምርጥ ምርጫዎ አድርገው ስለ ዘዘዙ እናመሰግናለን!
ትዕዛዝዎ ተልኳል።
የዕድል ቁጥርዎ: #[lucky_number]

---

TG's Restaurant ✨

Thank you for ordering with us!
Your food has been delivered. We hope you enjoy your meal!
Your lucky number: #[lucky_number]

🎯 Daily lottery draw happens at 10:00 PM. Good luck!
```

**Where `[lucky_number]` comes from:**
- Pull from `lottery_entries` table where `order_id` matches this order
- If no lucky number exists for this order → show the button greyed out with tooltip "Lucky number not generated yet"
- If lucky number exists → button is active, clicking copies the full message with the real number inserted

**UI placement:**
- On the completed order card in My Deliveries tab → below the "Delivered ✅" status badge
- Button text: "📋 Copy Lucky Number Message"
- After copying: button text changes to "✅ Copied!" for 2 seconds then reverts
- This replaces the need for the delivery staff to remember or look up the customer's lucky number — it's right there on the completed order
